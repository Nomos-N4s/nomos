# Stronger prediction tests and expanded property-based coverage — week of 2026-07-29

A reliability-focused week: the formal prediction suite and core modules are harder to break, and every run is now exercised end-to-end.

## Updates

- **More robust formal predictions.** The timelock prediction (P7) now drives contracts through the real lifecycle instead of poking at internal counters, so `ENACTED → ACTIVE` transitions are validated the same way production code performs them. The multisig prediction (P10) now consults the constitutional tier rule directly, removing a fragile string-based lookup. Both predictions in `prove.py` are more stable across refactors. See the [Ulysses Contracts chapter](/book/chapter-03/03-ulysses-contracts) and the [Identity Layer chapter](/book/chapter-04/04-identity-layer) for the underlying models.
- **Property-based coverage across contracts, Identity Layer, and TEE.** New Hypothesis-driven tests explore mask merging, enforcement, and timelock behavior for contracts; tier rules, multisig thresholds, and ontology hashes for the Identity Layer; and watchdog logic, Merkle trees, and constant-time operations for the TEE. This significantly widens the input space that each module is checked against.
- **End-to-end pipeline test.** A mini benchmark → analysis → figures → export run now executes as an integration test, so regressions in the full pipeline are caught before release. See the [experiment protocol](/book/appendix-d-experiment-protocol) for how the pipeline fits together.
- **Benchmark smoke test in CI.** A short benchmark run — including CSV export — now runs on every change, so basic breakage in the CLI or reporting path is caught immediately. Details on the CLI options remain in the [experiment protocol](/book/appendix-d-experiment-protocol).
