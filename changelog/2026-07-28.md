# Experiment scenario API refresh — week of 2026-07-28

A quiet week focused on making the experiment scenario API easier to build on.

## Updates

- **Streamlined experiment scenario API.** Building a custom scenario now only requires implementing a single step method. Reward and transition logic remain available as optional hooks, so existing overrides keep working while new scenarios get a simpler starting point. See the [experiment protocol](/book/appendix-d-experiment-protocol) for scenario reproducibility guidance.
- **Centralized step bookkeeping.** Scenarios now share a common public step entry point that handles counters, termination, and result assembly. Custom scenarios inherit this behavior automatically instead of reimplementing it.
- **Per-step metric deltas.** Step results include a `metrics_delta` field so downstream tools (dashboards, logs, RL adversary runs) can attribute changes to individual steps rather than diffing full metric snapshots. Relevant to the [RL adversary](/book/appendix-e-rl-adversary).

## Fixes

- **Fixed experiment class hierarchy.** Resolved an inconsistency in how scenarios inherited from the base class, so all built-in scenarios — GridWorld, Deadlock Maze, Drift Lab, Temptation Bank, and the Safety-Gymnasium and Minigrid wrappers — now share the same step contract.
